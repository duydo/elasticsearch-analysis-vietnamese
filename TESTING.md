# Testing Guidelines

This document explains how to build and run the test suite for the **Elasticsearch Vietnamese Analysis Plugin**.

---

## Prerequisites

### 1. Java 21+

The project requires Java 21. Confirm with:

```sh
java -version
```

### 2. Maven 3.8+

```sh
mvn -version
```

### 3. CocCoc Tokenizer Native Library (required for tokenization tests)

Tests that exercise actual Vietnamese tokenization (`VietnameseAnalysisTests`, `scripts/smoke_test.py`) need the CocCoc native library on the system.

**Build and install:**

```sh
git clone https://github.com/duydo/coccoc-tokenizer.git
cd coccoc-tokenizer && mkdir build && cd build
cmake -DBUILD_JAVA=1 ..
make install

```

Tests look for the library in `/usr/local/lib` by default. If it is installed elsewhere, pass
`-Dtokenizer.lib.path=/path/to/lib` to Maven.

**Verify the library is installed:**

```sh
/usr/local/bin/tokenizer "Cộng hòa Xã hội chủ nghĩa Việt Nam"
# Expected output: cộng hòa    xã hội    chủ nghĩa    việt nam
```

> **Note:** The unit test classes (`TokenTest`, `NativeMemoryTests`, `NamedComponentsTests`, `VietnameseAnalyzerTests`, `VietnameseConfigTests`) do **not** need the native library and can run anywhere.

## Running Tests

### All tests

```sh
mvn test
```

The build uses `maven-surefire-plugin` 3.5.2, which supports Java 21 and runs JUnit 4 tests via the `RandomizedRunner` that is already on the test classpath (pulled in by `elasticsearch-test:framework`).

### Skip tests (build the ZIP artifact only)

```sh
mvn package -DskipTests
```

### Run a single test class

```sh
mvn test -Dtests.class=org.elasticsearch.plugin.analysis.vi.VietnameseAnalysisTests
```

### Run a single test method

```sh
mvn test \
  -Dtests.class=org.elasticsearch.plugin.analysis.vi.VietnameseAnalysisTests \
  -Dtests.method=testVietnameseAnalyzer
```

### Reproduce a specific randomized failure

Each test run prints a seed, e.g. `SEED: 1A2B3C4D5E6F`. Pass it back to replay the same execution order:

```sh
mvn test -Dtests.seed=1A2B3C4D5E6F
```

## Test Classes

| Class | Type | Needs native lib |
| --- | --- | :---: |
| `com.coccoc.TokenTest` | Unit — native enum mapping | No |
| `com.coccoc.NativeMemoryTests` | Unit — `Unsafe` (JDK 21) and FFM (JDK 22+) native memory readers | No |
| `o.e.p.a.vi.lucene.VietnameseAnalyzerTests` | Unit — stop-set loading & analyzer construction | No |
| `o.e.p.a.vi.VietnameseConfigTests` | Unit — settings injection and parsing | No |
| `o.e.p.a.vi.NamedComponentsTests` | Unit — `named_components.json` matches the `@NamedComponent` annotations | No |
| `o.e.p.a.vi.VietnameseAnalysisTests` | Plugin loaded by Elasticsearch's stable plugin machinery — tokenization, offsets, settings | Yes |
| `scripts/smoke_test.py` | End-to-end through the REST API of a real node (Docker) | Yes |

### Unit tests (no native library)

These run fast and are safe to execute in any CI environment without the CocCoc library:

- **`VietnameseAnalyzerTests`** — verifies that `WordlistLoader.getWordSet` correctly loads `stopwords.txt` (the replacement for the Lucene 10 / ES 9.x incompatible `loadStopwordSet` overload), checks known stop words are present, and confirms the analyzer constructs cleanly with default and custom stop-word sets.

- **`VietnameseConfigTests`** — injects settings the way Elasticsearch does (through `SettingsInvocationHandler`) and verifies that `VietnameseConfig` reads all four tokenizer settings, applies the defaults and maps them to the right `TokenizeOption`.

- **`NamedComponentsTests`** — `src/main/plugin-metadata/named_components.json` is checked in instead of being generated by a Gradle plugin, so this test runs Elastic's `NamedComponentScanner` over the compiled classes and fails if the file is out of date.

### Analysis tests (native library required)

`VietnameseAnalysisTests` loads the plugin the way Elasticsearch loads a stable plugin (`StablePluginTestHelper`: components from `named_components.json`, instantiated by `AnalysisModule` with injected settings) and exercises:

- Component registration (`vi_analyzer`, `vi_tokenizer`, `vi_stop`).
- Tokenization, offsets (including through char filters) and tokenizer reuse.
- Tokenizer settings, stop word settings (`_vi_`, `_none_`, lists, `stopwords_path`, `ignore_case`) and invalid settings.

### Smoke test against a real node (native library required)

Unit tests cannot load a stable plugin into a running node, so `scripts/smoke_test.py` checks the installed plugin through the REST API: every documented setting, invalid settings (HTTP 400), search with highlighting and concurrent indexing. CI runs it on the oldest supported Elasticsearch release and on a newer one:

```sh
docker build --build-arg ES_VERSION=9.5.5 -t es-vi .
docker run -d --name es-vi -p 9200:9200 -e discovery.type=single-node -e xpack.security.enabled=false es-vi
docker exec es-vi bash -c 'mkdir -p config/analysis && printf "thông tin\nviệt nam\n" > config/analysis/vi_stop.txt'
python3 scripts/smoke_test.py http://localhost:9200
```

## Writing New Tests

### Unit tests (no native library)

Extend `org.elasticsearch.test.ESTestCase`:

```java
public class MyTest extends ESTestCase {
    public void testSomething() {
        // standard JUnit-style assertions via ESTestCase helpers
        assertEquals("expected", "actual");
        assertTrue(someCondition);
    }
}
```

### Tokenization tests (native library required)

Use `StablePluginTestHelper.createTestAnalysis` to get a `TestAnalysis` wired the way Elasticsearch wires the stable plugin, and Lucene's `BaseTokenStreamTestCase` assertions for token-level checks. Skip the class when the native library is missing:

```java
public class MyTokenizerTests extends ESTestCase {
    @BeforeClass
    public static void assumeNativeLibrary() {
        assumeTrue("Requires the CocCoc native library", NativeLibrary.AVAILABLE);
    }

    public void testTokenization() throws IOException {
        TestAnalysis analysis = StablePluginTestHelper.createTestAnalysis(createTempDir(), Settings.EMPTY);
        try {
            Tokenizer tokenizer = analysis.tokenizer.get("vi_tokenizer").create();
            tokenizer.setReader(new StringReader("công nghệ thông tin"));
            assertTokenStreamContents(tokenizer, new String[]{"công nghệ", "thông tin"});
        } finally {
            analysis.indexAnalyzers.close();
        }
    }
}
```

For behavior that needs a running node, add a check to `scripts/smoke_test.py`.

## Troubleshooting

| Error | Cause | Fix |
|---|---|---|
| `UnsatisfiedLinkError: no coccoc_tokenizer_jni` / tests skipped with "Requires the CocCoc native library" | Native library not on JVM's library path | Follow the [install steps](#3-coccoc-tokenizer-native-library-required-for-tokenization-tests) above; `VietnameseAnalysisTests` skips automatically when the library is absent |
| `UncheckedIOException: Unable to load default stop word set` | `stopwords.txt` missing from classpath | Ensure `src/main/resources/org/elasticsearch/plugin/analysis/vi/lucene/stopwords.txt` exists and run `mvn compile` |
| Tests not discovered / 0 tests run | Test class names don't match surefire's default pattern | Ensure test classes end with `Test`, `Tests`, or `TestCase` |
